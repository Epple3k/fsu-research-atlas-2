01 / The problem

Search finds papers. It does not make a research system legible.

University research is distributed across departments, disciplines and thousands of individual publications. A person trying to understand the larger pattern has to assemble it manually.

Existing publication databases are useful when the user already knows what paper, author or subject to search for. They are less useful for exploratory questions: Which fields are becoming more interdisciplinary? Where are strong connections forming? What evidence supports that conclusion?

The tempting solution is to place a conversational AI over the dataset. That makes querying easier, but creates a new problem: a fluent answer can feel authoritative even when the path from source data to conclusion is invisible.

The design problem was not simply “How can AI answer questions about research?” It was “How can an answer remain inspectable after AI makes the dataset easier to ask?”

Provisional primary user

A university research strategist investigating cross-disciplinary activity before deciding where to focus outreach or further analysis. This user definition is a design hypothesis until interviews with research-adjacent users are completed.

JOB 01

Identify a relationship worth investigating without scanning thousands of papers.

JOB 02

Understand whether a claim describes current volume, change over time or interpretation.

JOB 03

Inspect the exact papers behind a conclusion before acting on it.

02 / Hypothesis

Convenience without blind trust.

AI can make a large research dataset easier to interrogate, but users should never have to accept its numerical claims on fluency alone.

My hypothesis was that every generated conclusion should remain visually and interactively attached to the evidence that produced it. The AI can decide which constrained analysis tools to call; it cannot invent an unsupported number or detach a claim from its source records.

04 / Design decisions

The architecture is part of the interaction design.

The trust model is not a disclaimer added to the interface. It shaped what the agent may do, what the frontend will display and how a user moves through the result.

Claims are objects, not prose.

An AI answer is decomposed into selectable claims. Selecting one highlights the exact field relationship and loads its supporting papers.

Tradeoff: the response is less conversational, but far easier to inspect and challenge.

The network explores; text specifies.

A ranking is precise but hides relational structure. A network exposes structure but is harder to read exactly. I use the network for orientation and claim cards for precise values.

Tradeoff: two coordinated views add complexity, so selection state must remain synchronized.

Observation and interpretation have different voices.

Measurements use the sans-serif product voice. Interpretive conclusions use a contrasting serif voice, creating a subtle boundary between what the dataset reports and what the system infers.

Tradeoff: typography supports the distinction, but wording and evidence access still carry the real burden.

The model never owns the numbers.

The agent can only call constrained tools that return observations, field pairs and work IDs. The browser reconstructs visible claims from its own data before rendering them.

Tradeoff: this limits free-form expression, but makes unsupported quantitative claims structurally harder to display.

05 / Iteration

A failure in the evidence chain changed the implementation.

A technically correct answer is still a product failure if the interface cannot expose how it was produced.

Observed failure

The agent answered an open-ended question with real tool output, but the UI rendered no clickable evidence.

The first server implementation only collected provenance when the model used a direct link lookup. For “most interconnected” questions, the model used a top-collaborations tool instead. The prose contained supported values, but the returned edge list was empty—breaking the product’s core promise.

I changed the server to capture evidence-backed field pairs from every relevant tool result and kept claim construction in the browser. I also raised the model’s output budget after tracing a second failure where tool calls were silently truncated on harder questions. The iteration was not “make the AI sound better.” It was “make the evidence contract survive different agent behavior.”

06 / Evaluation

Next: test whether visible provenance changes behavior.

The working product proves the mechanism. It does not yet prove that the mechanism improves comprehension or calibrated trust.

The prepared study uses two otherwise similar views: a control view in which claims can be read and highlighted, and the evidence-first view in which the underlying papers are available inline. Six to eight participants will complete matched research-investigation tasks in counterbalanced order.

What would count as learning

If evidence visibility raises trust indiscriminately, the design may create false confidence rather than calibrated trust. More encouraging evidence would be that participants verify sources more often, explain conclusions more accurately and describe clearer reasons for trusting or questioning a claim.

The study protocol, moderator script and session record are included in the public repository so the evaluation can be reviewed and repeated.

07 / Reflection

Trust is something an interface lets a user do.

The most important outcome is not the network itself. It is a reusable model for keeping machine-generated interpretation connected to inspectable records.

This prototype taught me to treat data provenance as a user interaction rather than a backend property. A citation stored somewhere in the system is not enough. The person using the product needs a visible path from question, to claim, to relationship, to source—and that path must survive the unpredictable ways an agent may choose to solve a problem.

The next iteration will be determined by observed user behavior: where people hesitate, what they assume a line or claim means, whether they inspect evidence, and whether the interface helps them form a reasoned level of trust rather than simply a higher one.
